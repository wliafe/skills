# 理解项目

先理解项目怎么用、怎么跑、各部分怎么分工，再读具体实现。整体了解项目时走完整流程。为已有任务补背景时沿同一顺序，只深入与任务相关的部分，掌握后继续原任务。项目理解阶段用只读操作查证。安装依赖、启动服务、修改项目和创建 worktree 等操作按原任务范围执行。

## 1. 完整读 README 和必要文档

确认项目根目录和阅读范围。在 Git 仓库中，记录当前分支和提交，基于实际工作树查证。完整读根 README，长文件分段读完。顺着它补读有关项目用途、开发约定、架构和运行方式的说明。没有 README 或说明不完整时，用项目文档、子项目说明和配置补齐，并标出缺口。

多入口仓库先弄清根级结构，列出主要子项目或入口的用途。用户已指定目标时沿该目标读。用户未指定时挑一条明显的主线，说明为什么选它。入口选择会改变结论且没有合理默认时，再问用户要深入哪块。

进入下一步前，能说明这个项目做什么、主要由哪些部分组成，以及接下来应该核对哪些使用或运行说明。

## 2. 查清环境和启动方式

先从文档找运行时版本、依赖管理方式、配置来源、外部服务和启动步骤，再用清单、锁文件、版本文件、示例配置或 CI 核对必要信息。环境变量只记录相关键名和来源，避免读取或输出凭据。不同来源的要求有差异时保留各自依据，能确认时说明适用场景，例如开发版本与最低兼容版本。

文档缺失、只给演示代码或与仓库配置对不上时，从实际入口补查。按项目类型查 `main`、Shell 脚本、任务定义、包清单脚本、CLI 注册、容器入口或框架的应用发现方式。库项目查公开导出及调用示例。此时只读到能确认入口的程度，业务实现留到第四步。

进入下一步前，能指出从哪个目录、用什么环境和配置、通过哪条命令或调用方式进入哪个组件。只做静态核对的命令标明「未运行」。

## 3. 理解目录结构与职责

先看顶层，定位入口、核心实现、共享模块、配置、脚本、测试、文档和示例。再逐层展开与项目主线或用户任务有关的目录，找到具体职责及模块之间的边界。用子目录文档、清单、导出、注册关系或代表性文件佐证。仅凭目录名得到的结论标为待核实。

进入下一步前，应能用几条路径说明运行入口、核心实现、配置与测试分别去哪找。

## 4. 带着问题定向读代码

选一条代表性路径，例如一次请求、一条 CLI 命令、一次训练或批处理，或一个公开 API 调用。从已确认的入口追到关键模块和输出，必要时对照相关测试。若链路取决于运行时注入、生成产物、部署参数或外部服务，说明静态阅读追到哪里、还缺哪项证据。

能讲清关键输入、处理过程和产出就收束。只有当另一条路径会改变对当前任务的判断时，才继续追查。

## 交付与停止标准

整体阅读在对话中交付四部分。重要结论附文件路径和行号或链接，明确区分已核对、推断和待确认的内容。

1. 项目概览和本次阅读范围。
2. 环境前提、工作目录、配置来源、启动或调用入口及核验状态。
3. 关键目录及职责。
4. 一条代表性代码路径，以及影响后续工作的未知点。

读完后应能用证据回答「项目做什么、怎么进入这条运行路径、各部分去哪找、核心行为怎么实现」。若只是为当前任务补背景，够用后直接继续该任务。
