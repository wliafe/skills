# Notion 目录树读取与 MCP 接入

使用当前会话可用的 **Notion MCP**。本技能只提供 **MCP 连接检查**与**沿目录树按需读取**的通用流程，不内置任何工作区的维护规则、收集流程、归档周期、结构演进条件、私有页面 URL、Page ID 或专属分区名。

**单独点名不默认写**：当用户仅点名本技能而未附带具体要求时，不自动收集对话或写入 Notion；仅做只读连接与入口定位检查，或请用户说明要读取或处理的目标。

## 一、MCP 只读检查与排查

按当前会话实际暴露的工具名称映射搜索、读取与关联查询能力。执行 Notion 任务前，先做一次只读检查（如 `search` 或 `fetch`），不以写工具测试连接。

工具未暴露、未授权或调用失败时，按 [MCP 检查与连接](references/mcp-setup.md) 排查并说明缺项；不自动安装插件或扩大工作区权限。

## 二、沿目录树按需读取

按 [目录树读取方法](references/tree-navigation.md) 从入口逐层下钻：

1. **定起点**：优先使用用户或指令指定的入口；未指定时以通用标题词（如「工作台」「目录」「索引」）`search` 定位根入口并 `fetch`。
2. **读地图与层级**：从根页 `fetch` 结果查看正文导航指针（页面提及、内嵌子页、索引链接）及树结构元数据（`<ancestor-path>` 与子页列表）。若根页指向独立的索引或活地图页，先 `fetch` 该页缩小范围，不横向遍历无关顶层分支，不一次扫全库。
3. **按需下钻与止步**：只选与当前任务最相关的 1～2 条分支逐层 `fetch`，读到足以回答当前问题的最细页面即停。
4. **搜索补充核对祖先**：仅当目录索引未覆盖深层条目或需跨分支确认归属时，辅以关键词 `search` 定位候选；命中后必须 `fetch` 核对 `<ancestor-path>`、上级说明与状态标注，避免把历史或归档内容当成现行事实。

## 三、写入、维护与整理前的桥接动作

只有当用户或任务明确要求**写入、补记、归档、移动或整理结构**时，才沿目录树定位并完整 `fetch` 工作区内的**实时维护指南**（及拟改动分区的局部说明），并严格以 Notion 中的现行指南为准执行。找不到维护指南或授权不足时，停止写入并如实报告查找路径。

## 四、读取证据与汇报纪律

空白会话看不到页面正文，必须实际调用 `fetch` 后再作答，不得凭链接或记忆猜测。汇报时清晰区分「已 `fetch` 核实的内容」「未读取的分支」与「实际读取路径及核验边界」。
